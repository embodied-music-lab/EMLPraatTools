## 1. Environment — settled, do not re-litigate

### Praat binaries: download them, do not build

**6.6.30 is no longer on the Praat website** — `fon.hum.uva.nl` carries only
7.0.00, 6.4.30 and 6.1.15. It **is** on GitHub releases, under two names
that are easy to get wrong:

- the release lives in **`praat/praat.github.io`**, not `praat/praat`
- the Linux asset is **`praat6630_linux-x64v3.tar.gz`**; the older
  `linux-intel64` naming is retired and 404s

```
curl -fL -o p.tar.gz https://github.com/praat/praat.github.io/releases/download/v6.6.30/praat6630_linux-x64v3.tar.gz
tar xzf p.tar.gz && chmod +x praat && ./praat --version
```

**Release-asset downloads are not repo-gated.** They come off a CDN the
egress proxy permits, even though `api.github.com/repos/praat/praat` is
refused. Any tagged Praat build is one `curl` away.

Building from the `v6.6.30` tag also works (`sudo apt install make rsync
pkg-config gcc g++ libgtk-3-dev libasound2-dev libpulse-dev libjack-dev`,
then `make PRAAT_ARCH=x64v3 PRAAT_COMPILER=gcc -j2`) but takes 30+ minutes
on two cores. Do not do it. Download.

7.0.00 (`praat7000_linux-x64v3.tar.gz`, 4 August 2026) is the differential
probe target — Ian's ruling is 6.6.30 for the drive, 7.0.00 probed
separately, not swapped in.

`add_repo` is still not exposed as a tool. No mid-session control to add a

## 6. Rig notes — two fixes committed, one trap to remember

**`curpause` was rewritten** (`harness/gui.sh`). The old name-search
implementation fails twice over: Praat leaves every dismissed pause window
in the X tree, unmapped and still carrying its old name, so the search
returns a growing list of dead ids; and the *live* dialog is frequently
absent from `xdotool search` results while plainly visible and accepting
clicks. **`xdotool getactivewindow` returns it every time.** `pgeom` and
`needclear` work again, and `curwin` was added for GTK entry focus.

**`emlmenu` was fixed** to use `windowactivate --sync` then `windowfocus`
rather than bare `windowraise`, matching every other primitive.

**The trap that remains:** a modal Praat *error* window grabs input and
silently swallows every subsequent click. When a click appears to do
nothing, take a screenshot before retrying. A script syntax error of your
own making will produce one.

Menu geometry was re-derived from a live screenshot and is **unchanged**
from `harness/MENU_MAP.md`. Dialogs centre at x≈438, width 524.
