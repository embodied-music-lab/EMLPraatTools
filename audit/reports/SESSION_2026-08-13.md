## 1. The pause-dialog focus ring, measured (`tabwalk`, v44)

**Wrong before:** `harness/gui_e2e/run.sh` carried TWO incompatible laws for
where Tab goes and had measured neither. Header: Tab "visits every focusable
widget". Case table sixty lines below: Tab "walks the button row exactly".
The four counts in that table had never been exercised, because the harness
returned before reaching a dialog that needed one — so the file was at once
the only statement of the law and unable to test it.

**Measured:** 44 presses over every button-row shape the plugin raises.

- Tab visits every FIELD before any button. The table's "Column Mapping
  tabs=4" lands on **Go Back** — the harness would have looped forever.
- Return in a text entry or on a checkbox presses the **default** button, not
  the focused widget. An off-by-one therefore does not hang; it silently
  presses something else and the run looks healthy.
- Return on an optionmenu opens its dropdown and dismisses nothing.
- `folder:` is **not an entry**. It is a multi-line GtkTextView with a Browse
  button, and GTK text views swallow Tab AS A LITERAL TAB CHARACTER. On the
  Save Figure shape no forward count from 0 to 13 reaches a button, and every
  Tab sent is appended to the output folder path. Photographed.
- Return on that Browse button opens a modal chooser that eats every later key.
- The default button is the SECOND-TO-LAST integer of `endPause:`. Every
  expected value above depends on this and nothing had established it.

**The replacement:** the walk runs BACKWARD. Focus starts at ring position 0,
so one `shift+Tab` wraps to the last widget — the last button. `shift+Tab` xN
presses the Nth button from the end, on every shape, without entering a field.
The count then comes from the `endPause:` list, which is static per dialog.

## 2. The graphs path exported the wrong CSV format (v45, v46)

**Wrong before:** the graphs form's Exp CSV button called `@emlExportStatsCSV`
directly — the legacy single long-format file — while the stats menu wrote
broom's three frames for the same analysis. Two compounding causes: the
migration fork lived INSIDE `@emlWrapperExportCSV` and was unreachable, and
the annotation bridge never declared into the tidy/glance/augment collectors.

**Why nothing caught it, and this is the transferable part:**

- v20/v21 enumerate the **stats-menu orchestrators**. v21's own words: "every
  file written by the orchestrator the menu calls." A second exporter reached
  from the graphs form is outside that enumeration BY CONSTRUCTION.
- `coverage.R` compares rendered cases against claimed cases PER ARTEFACT. It
  catches an unclaimed case and even an artefact with no reader. It cannot
  catch a path that produces **no artefact at all** — and that button had
  never been pressed by any harness.
- **The migration was scoped by the wrong unit.** Scoped over CALL SITES of
  the exporters instead of over menu paths, `eml-graphs-form.praat` would have
  appeared on day one: there have only ever been two live callers of
  `@emlExportStatsCSV` and one of them was the graphs button.

**Fixed by DRY, per author direction:** no procedure rewritten. The fork was
extracted verbatim as `@emlExportResultFiles` and both buttons call it; the
bridge gained the same `@emlDeclare*Result` calls the orchestrators already
make. The three reporters the graphs path uses were ALREADY shared — the
stats orchestrators call into them across the file boundary — so the only
thing missing was the declaration tail.

**v46 is the guard, and it is static on purpose.** The population that needed
checking was never a set of results; it was a set of call sites, which is a
property of the source. It needs no harness run, so it cannot be outrun by a
button nobody presses.

## 5. Praat facts established (measured, this session)

- `shift+Tab` xN presses the Nth button from the END of any pause dialog.
- `folder:` renders as a GtkTextView; Tab inserts a literal tab into it.
- Escape dismisses a GTK chooser; on a pause form it presses button 1.
- The default button is the second-to-last integer of `endPause:`.
- **`Read from file:` opens a script in a ScriptEditor iff the file begins
  `#!`** — Praat's own documented behaviour, confirmed under Xvfb.
- `Open Praat script:` opens an EMPTY editor plus a file chooser, ignoring the
  path, and blocks. `New Praat script` opens an empty editor and returns.
- Bare `info$` is not a variable; `nocheck x$ = info$` leaves `x$` unset.
- A menu script must include the barrel by its neighbour name — a relative
  path inside an included file resolves against the TOP-LEVEL script's folder.
- A menu script cannot be `include`d by anything that already included the
  barrel: `include` is a textual paste with no guard, so the plugin lands
  twice and Praat refuses with "Duplicate label".

## 6. The save panel (`@emlSavePanel`, eml-output v2.2)

Built 13–14 August. Before it, a user who had run an analysis and drawn a
figure had **three separate saves in three places, each with its own folder
memory and its own naming**, and no way to save the Info window at all —
`@emlSaveInfoToFile` existed, was broken, and was wired to nothing.

**One panel, reached from every save journey.** Tickboxes for Figure PNG,
Results CSV and Report from the Info window; one `folder:`; one `word:` for
the name. Everything ticked is written to that folder under that stem, so the
outputs of one analysis stay a set. The figure's separate legend (D136) is a
second file sharing the stem, because a figure is not complete without it.

**Where it is reached from.** The nine stats wrappers and the wizard: their
`CSV` button became `Save` and calls the panel with `offerFigure = 0`. The
graphs form's Graph Complete dialog: `Save Figure` and `Exp CSV` are gone,
replaced by three FIXED buttons — `Done`, `Save`, `Redraw` — and `Save` calls
the panel with `offerFigure = 1`. Fixed matters: the old row appeared and
vanished with what the draw produced, so the button count was not knowable
from the source, which is what a driver needs.

**Nothing was rewritten**, per author direction. The panel calls
`@emlExportResultFiles` (the migration fork, extracted verbatim earlier in the
session), `@emlSaveInfoToFile`, `@emlGenerateUniquePath`, and
`@emlRecordStep`. It owns no writer of its own.

**Defects the build surfaced, each of which would have shipped:**

| defect | shape |
|---|---|
| `figure_png` — "Unknown variable" | Praat lowercases **only the first character** of a field label when making the variable name. `boolean: "Figure PNG"` is `figure_PNG`. The save silently did nothing, which is the failure a tickbox panel is most able to hide |
| `.content$ = info$` | bare `info$` is not a variable. `info$ ()` is the function. The procedure had never been called, so had never run |
| two-slot ceiling on extra result tables, `exitScript:` on a third | a hard kill on a user-reachable path. Now a counted list |
| the report was invisible to the artefact collector | it globbed `.png` and `.csv` only, so a save that worked read as a save that half-worked |
| the figure was written to `/root` | `@emlSaveConfig` had persisted `lastPNGFolder` from an earlier drive. The run now deletes the config and sets `HOME` inside `out/` |

**`@emlDrawSeparateLegend` — invented, within an hour of the last invention.**
There is no such procedure. The legend is saved by `Select outer viewport:` on
the stored coordinates, writing, then `@emlAssertFullViewport` to put the
figure's extent back — otherwise a second Save from the same dialog writes the
legend again instead of the figure. Same failure mode as
`Open Praat script from file:` in §3: **read the source before calling it.**

**Proven end-to-end.** One press of Save wrote five files under one stem:
`.png` 62497, `_tidy.csv` 198, `_glance.csv` 137, `_effectsize_tidy.csv` 85,
`_report.txt` 2844.
