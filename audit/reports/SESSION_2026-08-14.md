## 1. Every non-graphing Save was dead (`857629a`)

**Wrong before:** all nine non-graphing call sites of `@emlSavePanel` — eight
stats wrappers and the wizard — pass `emlLastCSVFolder$`, and **nothing seeded
it.** The seed had lived INSIDE `@emlWrapperExportCSV`, the procedure the panel
superseded, so it was deleted along with the call:

```
if not variableExists ("emlLastCSVFolder$")
    emlLastCSVFolder$ = homeDirectory$
endif
```

Praat evaluates a procedure's arguments BEFORE entering it, so
`@emlSavePanel: 0, tableName$ + "_two-group", emlLastCSVFolder$` aborted with
"Unknown variable" on the FIRST press of Save in a session — and took the
user's analysis with it. Ten call sites, one of them ever pressed by a harness
(the graphs one, by `gui_e2e`); the other nine shipped dead.

**Why nothing caught it, and this is the transferable part:**

- **v46 passed throughout and every claim it makes was true.** The call site is
  there, it names the panel, the superseded procedure has no callers. A static
  call-site check can see that a CALL exists. It cannot see that an ARGUMENT is
  unbound.
- `harness/wrappers` asks only whether a script parses. **An unbound variable
  parses.**
- The first line of the panel's contract had never been executed on any of the
  nine paths, because nothing had ever pressed the button. §2 exists for this.

Seeded once at load in `eml-output.praat` — the file that defines the panel
owns the panel's state — not in ten wrappers.

**Three more fixes in the same commit:**

- **The fork's guard aborted on the case it guarded.** Praat does not
  short-circuit `and`: it evaluates both operands, so
  `if variableExists ("emlResult_declared") and emlResult_declared = 1` dies
  with "Unknown variable" exactly when the name is unset. Through the panel
  that is dead code, but `@emlExportResultFiles` is ALSO the code/API export
  path, and there the first call in a fresh session has nothing set. Nested
  ifs, the same law as the Kruskal bridge. Swept the tree: one occurrence.
- **"File name" became "Base name."** One press writes several files told apart
  by a suffix the procedure appends, so the old label described what the user
  typed and not what they got — typing `results.csv` produced
  `results.csv_tidy.csv` with nothing to say why. The readback moves to
  `base_name$` with the label, and the panel now lists its suffixes
  conditionally, because the panel is the only place the naming scheme is ever
  visible.
- **A timestamp on the proposed name.** `@emlFileStamp` gives
  `YYYYMMDD_HHMMSS`. It lands in the EDITABLE field, so a user who does not
  want it deletes it, and `@emlGenerateUniquePath` stays as backstop. That is
  the MATLAB/Audacity/OBS convention; SPSS and JASP prompt, Praat and `ggsave`
  overwrite. Deliberately NOT unified with the recorder's `emlRecordStamp$`,
  which stays human-readable because a person reads it at the top of an
  emitted script.

Also: the panel now `createFolder:`s the folder it was handed. `folder:` is a
freely editable field, so a user can name a folder that does not exist, and
without this the save died on the first write with Praat's own message —
"Cannot create file <path>. Hint: this is a folder, not a file" — which names
neither the cause nor the folder.

## 9. Praat facts established (measured, this session)

- **`and` does NOT short-circuit.** Both operands are evaluated before the
  operator applies, so `variableExists ("x") and x = 1` aborts with "Unknown
  variable" on precisely the case the guard was written to survive. Praat
  6.6.30. Nested ifs are the only safe form.
- **An optionmenu sits at focus ring position 0, and plain `Down` changes its
  selection WITHOUT opening the dropdown.** That is what makes a form with an
  optionmenu drivable: `Return` on one opens the dropdown and dismisses
  nothing, and forward Tab does not reach it (Tab x1 lands on Undo). Because
  `Down` leaves focus AT position 0, the reverse-Tab button count afterwards is
  unchanged.
- **`runScript:` re-bases relative includes against the CALLED script's
  folder**, and carries object selection into it. This is what lets a harness
  drive the SHIPPED wrapper instead of a transcription of it.
- **`date_iso$ ()` exists and is fixed width** — `2026-08-14T15:06:15+00:00`,
  every field numeric and zero-padded — where `date$ ()` gives a month NAME and
  a space-padded day, so slicing it needs a month table and a pad test.
- **Praat's error window has NO window name at all** — `_NET_WM_NAME` and
  `WM_NAME` both empty. A GUI harness that looks only for `Pause:` windows sees
  nothing, breaks its loop, and reports a short clean chain with no artefacts:
  **a hard failure reads as a mild one.** `savepaths` now treats any Praat
  window that is neither a pause form nor one of the three permanent windows as
  an error, photographs it and fails the leg — and that check caught a second
  failure the moment it existed.
- A fixed sleep after a press is a race and on 14 August it lost:
  `eml-compare-paired` reshapes its table before writing, the panel took longer
  than the five seconds allowed, and the leg reported three dialogs and no
  files while passing by hand every time. **A harness whose verdict depends on
  how fast the machine is that day is not evidence.** Waits are bounded now.
- GitHub's web upload form can ADD a file at a path and can never remove one;
  the per-file delete page is one commit per file and pending deletions do NOT
  accumulate across navigations (tested with a second file while the first was
  pending — the editor showed only the one). `99d0dd2` is that measurement,
  one file of the seventy-eight.
