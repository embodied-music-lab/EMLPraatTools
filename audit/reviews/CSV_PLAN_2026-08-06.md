# CSV export: the broom model

6 August 2026. Plan, not yet implemented.

## The decision

Three exports per analysis, named and shaped as R's **broom** package names and
shapes them:

| Verb | Unit of a row | File suffix |
|---|---|---|
| `tidy` | one row per **model term** | `_tidy.csv` |
| `glance` | one row per **model** | `_glance.csv` |
| `augment` | one row per **observation** | `_augment.csv` |

This replaces the current single six-column long file
(`table,analysis,term,term_type,field,value`). That file was built to be
schema-stable across every test, and it paid for that with a shape nobody
actually analyses in: every number is a string in a `value` column, and reading
it back means a pivot plus a type coercion before you can do anything.

Your objection was the right one — generate the right columns per test. broom
is exactly that idea with fifteen years of convention behind it, so we adopt
the convention rather than invent a parallel one. The practical payoff is that
`read_csv("anova_tidy.csv")` in R gives a data frame **identical in shape** to
`broom::tidy(aov(...))`, so any downstream code, table-making package
(`gt`, `flextable`, `modelsummary`) or plotting idiom written against broom
works on our output untouched.

"One row per subject" — the thing you named as standard — is `augment`. It is
the original data with model-derived columns appended, one row per
observation, which for a paired or repeated-measures design is one row per
subject per condition.

## Column vocabulary

Canonical broom names, used wherever the quantity exists. Nothing invented when
broom already has a name for it.

**tidy** — `term`, `estimate`, `std.error`, `statistic`, `p.value`,
`conf.low`, `conf.high`, `df`, `adj.p.value`, `contrast`, `null.value`,
`method`, `alternative`. ANOVA-family rows additionally carry `sumsq`,
`meansq`, `num.df`, `den.df`. Effect sizes ride as `effect.size` +
`effect.size.type` (`cohens.d`, `hedges.g`, `eta.squared`,
`partial.eta.squared`, `epsilon.squared`, `r`, `cliffs.delta`) — broom itself
omits effect sizes, so this is our one documented extension, kept to two
columns so it never collides.

**glance** — `nobs`, `statistic`, `p.value`, `df`, `df.residual`, `r.squared`,
`adj.r.squared`, `sigma`, `logLik`, `AIC`, `BIC`, `method`, `alternative`.

**augment** — every original column of the input table, unchanged and in
order, then `.fitted`, `.resid`, `.se.fit`, `.hat`, `.cooksd`, `.std.resid`.
Leading dots are broom's convention for derived columns and are what stops a
derived column colliding with a user's column named `resid`.

A test emits only the columns it can defend. No zero-filling, no placeholder
columns — the absence of `conf.low` means we do not compute an interval, and
that is information.

## Per-test specification

| Analysis | tidy rows | glance | augment |
|---|---|---|---|
| Describe column | one per column described; `term` = column name, `estimate` = mean, `std.error` = SEM | `nobs` | — |
| Check normality | one per column; `term` = column, `statistic` = W, `p.value`, `method` = "Shapiro-Wilk" | `nobs` | `.resid` = value − mean, `.std.resid` |
| Two groups (Welch *t*) | 1 row; `term` = "g1 - g2", `estimate` = mean difference, `std.error`, `statistic` = t, `df`, `p.value`, `conf.low/high`, `effect.size` = d | `nobs`, `method`, `alternative` | group, value, `.fitted` = group mean, `.resid` |
| Two groups (Mann-Whitney) | 1 row; `statistic` = U, `p.value`, `effect.size` = r or Cliff's δ | `nobs`, `method`, `alternative` | group, value, rank |
| Paired / repeated (2 levels) | 1 row; `term` = "c1 - c2", `estimate` = mean of differences, `std.error`, `statistic` = t, `df`, `p.value`, `conf.low/high`, `effect.size` = dz | `nobs` (= n pairs), `method` | **one row per subject**: id, c1, c2, `.resid` = difference |
| One-way ANOVA | one per term + `Residuals`; `df`, `sumsq`, `meansq`, `statistic`, `p.value` | `nobs`, `r.squared`, `adj.r.squared`, `sigma`, `statistic`, `p.value`, `df`, `df.residual` | group, value, `.fitted`, `.resid`, `.std.resid` |
| Tukey HSD | one per contrast; `contrast`, `estimate`, `conf.low/high`, `adj.p.value`, `method` | — (belongs to the parent model) | — |
| Kruskal-Wallis | 1 row; `statistic` = H, `df`, `p.value`, `effect.size` = ε² | `nobs`, `method` | group, value, rank |
| Dunn post-hoc | one per contrast; `contrast`, `statistic` = z, `p.value`, `adj.p.value`, `method` | — | — |
| Two-way ANOVA | one per term A, B, A:B, `Residuals` | `nobs`, `r.squared`, `sigma`, `df.residual` | both factors, value, `.fitted`, `.resid` |
| RM-ANOVA | one per term + `Residuals`; plus `gg.epsilon`, `hf.epsilon`, `df.gg`, `p.value.gg` | `nobs`, `n.subjects`, `partial.eta.squared` | id, condition, value, `.fitted`, `.resid` |
| Friedman | 1 row; `statistic` = χ², `df`, `p.value`, `effect.size` = Kendall's W | `nobs`, `n.subjects`, `method` | id, condition, rank |
| Correlation | 1 row; `estimate` = r (or ρ/τ), `statistic` = t, `df`, `p.value`, `conf.low/high`, `method`, `alternative` | `nobs`, `method` | x, y, `.fitted`, `.resid` |
| Linear regression | one per coefficient incl. `(Intercept)`; `estimate`, `std.error`, `statistic`, `p.value`, `conf.low/high` | `r.squared`, `adj.r.squared`, `sigma`, `statistic` = F, `p.value`, `df`, `df.residual`, `nobs`, `AIC`, `BIC` | x, y, `.fitted`, `.resid`, `.se.fit`, `.hat`, `.cooksd`, `.std.resid` |
| Pairwise comparisons | one per contrast; `contrast`, `estimate`, `std.error`, `statistic`, `df`, `p.value`, `adj.p.value`, `method`, `effect.size` | `nobs`, `method` (adjustment family) | — |
| LMM | `effect` = `fixed` \| `ran_pars` per broom.mixed | `nobs`, `n.groups`, `AIC`, `BIC`, `logLik` | id, fitted, resid | 

LMM stays disconnected from the menus per the earlier ruling; the spec is
recorded so re-enabling it is not a redesign.

## Future-proofing: the contract a new test declares

The point of failure to design against is a test added in six months that
quietly emits a malformed file, or emits nothing and nobody notices. So the
writer is not a free-form append — a test **declares** its rows and the writer
enforces the shape.

```praat
@emlResultBegin: tableName$, "One-way ANOVA"

@emlTidyRow: "voice_type"          # starts a term row
@emlTidyNum: "df", 2
@emlTidyNum: "sumsq", 412.6
@emlTidyNum: "statistic", 13.70
@emlTidyNum: "p.value", 0.00002
@emlTidyStr: "method", "One-way ANOVA"

@emlTidyRow: "Residuals"
@emlTidyNum: "df", 42
...

@emlGlanceNum: "nobs", 45
@emlGlanceNum: "r.squared", 0.395

@emlAugmentFrom: tableId          # carries the input columns through
@emlAugmentNum: ".fitted", .rowIndex, .fitted
@emlAugmentNum: ".resid",  .rowIndex, .resid

@emlResultWrite: folder$, baseName$
```

Five properties this buys, each of which is a bug the current exporter has had
at least once:

1. **Column union per file, computed at write time.** A term row that sets
   `sumsq` and one that does not both write valid CSV; the second gets an empty
   cell, not a shifted row.
2. **Name validation against the vocabulary above.** `@emlTidyNum: "pvalue"`
   is refused at the call site with the correct spelling in the message, so a
   typo cannot silently create a second column that no downstream code reads.
3. **Undefined is empty, never `0`, never `--undefined--`.** R reads an empty
   cell as `NA`, which is what it means. The current exporter writes literal
   `0` into six descriptive slots that are simply not computed on the
   correlation path.
4. **A file with no rows is not written at all**, and the caller is told which
   of the three were skipped and why. An empty `_augment.csv` with a header is
   indistinguishable from a failed export.
5. **One writer, so RFC 4180 quoting is solved once.** Group labels with
   commas, quotes or newlines are the realistic case in this field —
   `"Soprano, lyric"` is a perfectly ordinary level name.

Adding a test means declaring rows. Adding a *column* to the vocabulary means
one edit to the vocabulary table and one line in the validation script. A test
that declares nothing produces nothing, loudly.

## Validation

The standing rule is that nothing counts as validated until an R script tests
the output, including the red-path input. This gets a stronger version, because
here R is not merely a check — it is the specification.

`validate/v17_broom_parity.R`:

1. Read the fixture the plugin analysed.
2. Fit the equivalent model in R (`t.test`, `aov`, `kruskal.test`, `lm`,
   `cor.test`, `friedman.test`, `TukeyHSD`, `afex::aov_ez` for RM).
3. Call `broom::tidy` / `glance` / `augment` on it.
4. Compare against our three CSVs **structurally** — same columns, same column
   order, same row count, same `term` values in the same order — and then
   **numerically**, column by column, to a stated tolerance.
5. Assert the red-path behaviour: blank cells read as `NA`, not `0`; no
   `--undefined--` anywhere; quoting survives a label containing a comma.

A per-test parity table in the run output, so a partial pass is visible as a
partial pass rather than rounding to "validated".

## Migration

The current single-file export is what the Draw path and every wrapper emit
today, and there are downstream files already written in it. So:

1. Build the writer and the vocabulary; land it with no caller changes.
2. Convert one test end to end — one-way ANOVA, because it exercises all three
   verbs and has the most existing evidence to diff against — and get
   `v17_broom_parity.R` green on it.
3. Convert the rest, one commit per test, each with its parity check.
4. Keep the old single-file export available behind an explicit
   "Legacy long format" option in the export dialog for one release, then
   remove it.

Step 2 is the one that proves the design. If broom parity on ANOVA is awkward,
better to find out having converted one test than twelve.
